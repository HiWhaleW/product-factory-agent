DETERMINISTIC CONTROL PLANE / V0.2

LLM 提建议，确定性代码决定状态

用户看到 12 个阶段；开发阶段在系统内部拆为后端与前端两个状态。feedback 只通过新 iteration/context/artifact 分支回到 alignment，不改写历史。

主状态流

01 alignmentG0 → mrd
02 mrdG1 → prd
03 prdG2 → solution
04 solutionG3 → tech
05 tech stackG4 → backend
06a backend通过测试 → frontend
06b frontend完整构建 → mvp
07 mvp→ internal acceptance
08 internalG5 → seed beta
09 seed beta证据包 → brd
10 brdG6 → release
11 release→ feedback
12 feedback↺ 新一轮 alignment

七个必审 Gate

G0 对齐Brief、用户、时间、不做范围
G1 市场需求MRD、证据、反证、替代方案
G2 产品范围PRD、核心闭环、验收、反指标
G3 方案User Flow、交互与关键取舍
G4 技术栈版本、成本、安全、数据与回退
G5 内部验收真模型、浏览器、Known Issues、内测范围
G6 商业发布内测数据、商业 BRD、费用、回滚

不可混用的三个控制面

产品状态机决定项目在哪个阶段，由 Gate 和退出证据约束。
Execution Task DAG决定内部任务依赖和是否可领取；不是用户产物图。
Artifact DAG向用户解释产物、版本和依赖；不展示隐藏任务状态。
PermissionRequest控制一次具体工具动作 allow/ask/deny，不能推进产品阶段。
AgentRun / RunStep记录有界循环、重试、暂停、恢复和外部副作用对账。
Governance Review全局 Prompt/Skill/Harness 回写使用独立治理审核，不占 G0-G6。
