D1-D2 补强的 6 项契约

这些是冻结前应写清的运行时语义，不是 D3 已实现事实。

1

Execution Task DAG

任务依赖、原子认领、owner、失败和取消，与 Artifact DAG 分离并建立引用。

2

Run Journal

run_id + step_id + input hashes + versions 支持恢复；副作用先对账再重试。

3

三态权限

allow / ask / deny；一次工具审批与 G0-G6 产品阶段闸严格分开。

4

上下文压缩

保留 tool use/result 对、未读结果、当前目标和完整 transcript 引用；摘要不升级为事实。

5

后台结果回注

完成事件回到原 Project/Task/Run/Context；Context 变化则标记 stale。

6

有界完成判断

确定性证据 → clean-context Reviewer → 人工 Gate；达到预算或重试上限即交还用户。

ALLOW已在 Agent、阶段、参数、路径、预算和副作用授权内。
ASK创建持久 PermissionRequest，群聊展示影响、范围和时效。
DENY硬禁止直接阻断，普通会话批准也不能绕过。

为什么不能直接复制实现

教学实现用最少代码解释概念；企业内部 Agent 需要面对绕过、并发、重启和审计。

示例做法对抗性攻击/故障产品工厂裁决
shell=True + 模型字符串连接符、重定向、环境展开、间接脚本可绕过浅层检查只通过 Codex CLI Adapter/结构化工具；路径、网络和副作用另行判定
命令子字符串黑名单编码、别名、脚本文件、工具变体导致漏拦或误拦按 Agent、阶段、目标、参数 Schema、信任边界和副作用组合授权
终端 input() 审批Web 请求断开、审批丢失、无时效/审批人/幂等PermissionRequest + Decision 持久化，并通过事件恢复
文件 JSON/JSONL 唯一状态进程崩溃半写、并发覆盖、跨实例争抢PostgreSQL 事务状态 + append-only Event；文件仅存产物
内存 Thread/Queue服务重启后任务和结果消失Run/Task 状态持久化；V1 可单 worker，但不能只靠内存
纯 LLM Goal Evaluator被执行者自述、提示注入或伪造测试文本误导确定性证据优先，Reviewer 只判语义，最终业务 Gate 留给人

不延长 10 日排期
