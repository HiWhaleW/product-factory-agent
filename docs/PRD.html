让非独立开发者也能控制一条可追溯的 AI 产品交付链路

产品工厂 Agent 通过项目群聊、4 个核心 Agent、累计 Artifact DAG、确定性状态机与人工闸，把一句想法推进为可运行、可验收、可交接并能持续迭代的内部 AI 产品。

销售复盘 Agent 是内部示范项目，为 seed_beta / Context v10，G6 未打开。产品工厂 Agent 是平台，下一步是 GitHub 更新和火山引擎 user-beta；平台测试环境不需销售复盘 Agent G6。

查看双环境运行说明

AI Native，不是“后台 + 聊天框”

Agent 主执行理解目标、规划、调用工具、生成产物和修订。
Harness 原生Context、Tool、Observation、Action、Permission 和 Artifact 是一等对象。
可信边界Reviewer、Gate、预算、幂等和审计约束 Agent 自主行动。

V1 只解决三件事

受控项目群聊按阶段拉入 AI PM、Builder、Reviewer；只共享版本化 Context Pack。
累计 Artifact DAG保留 MRD、PRD、方案、代码、MVP、内测、商业 BRD、发布与反馈的版本和依赖。
确定性控制面阶段、Gate、权限、预算、幂等和恢复由代码执行；Prompt 不能越权。

12 个本轮阶段

开发阶段内部固定后端→前端；“下一轮迭代”是反馈回到项目对齐的回环。

G0-G6 七个人工必审闸

G0对齐→MRD
G1MRD→PRD
G2PRD→方案
G3方案→技术
G4技术→后端
G5内验→种测
G6商业 BRD→发布

Gate 不替代一次性 PermissionRequest；全局 Prompt/Skill/Harness 回写走独立 Governance Review。

4 个核心 Agent

Factory Lead对齐、路由、状态、Context Pack、Gate 与交接。
AI PMMRD/PRD、内测分析和商业 BRD；不得伪造证据。
Builder方案、技术、后端→前端、测试和发布准备；不得自主发布。
Reviewer使用 clean context 独立审查文档、模型、工程与浏览器证据。

D1-D10 工程轴

  1. D1-D2：规格冻结，已通过
  2. D3-D4：最小控制面与 mock UI
  3. D5-D6：真实定义链路与 G0-G4
  4. D7：后端开发
  5. D8：前端开发与 MVP
  6. D9：独立 QA
  7. D10：G5 与 Beta Candidate

B1-Bn 证据轴

  1. 真实种子用户内测
  2. 达到样本/任务成功/反馈阈值
  3. 商业 BRD 与 G6
  4. 发布/交接
  5. 数据与反馈
  6. 创建下一轮分支

未验证假设与反指标

需要 dogfood 验证 4 Agent 协作成本、DAG 对非技术用户的解释力和 7 个 Gate 的停留/返工收益。虚假进度、越权调用、上下文污染和局部反馈触发全量重跑都属于反指标。
