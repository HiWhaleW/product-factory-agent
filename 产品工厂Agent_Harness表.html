Internal Product Design / v0.2

从一句产品想法，到一条可运行、可验收、可部署的 AI MVP

产品工厂是企业内部提效 Agent，不是开发平台。它以一个主 Agent 统一对人负责，按阶段加载角色与 Skill，并在不可替代的业务决策、验收、费用和外部发布处把控制权交还给人。

Harness 必须做

因为产品工厂是跨数天、跨角色、会调工具且会改变外部世界的 Agent。没有状态、权限、人工闸和验收证据，它就只是 Prompt 合集。

只做最小可执行 Harness

第一版不需要自研多 Agent 框架。一个主 Agent，加能力注册表、项目状态文件、工具策略、审核闸和审计日志即可。

角色不等于 Agent

17 个岗位是责任视角，Skill 是可执行方法，工具才是行动能力。只有需要独立上下文、并行或对抗审核时，才起独立 Agent。

资料审计结论： 公开 17 岗位体系与本地“14 身份库”不是同一套编号和文件。不能把两者直接合并后宣称已完整实现。下方注册表已按“可直接提取 / 可组合补齐 / 缺失待建”标注。

共享上下文：共享已批准事实，不共享整段脑内过程

新子 Agent 入群时，主 Agent 不应把所有群聊、所有文档和所有密钥一次性塞过去。正确做法是为每次任务生成一份有版本、有权限和有退出标准的 Context Pack。

L1 项目公共事实项目 Brief、目标、已批准决定、范围、术语表、当前版本和风险等级。所有参与者可读。
L2 当前阶段上下文本阶段的输入产物、退出证据、人工闸、未解问题和上游依赖。仅活跃团队可读。
L3 子 Agent 任务包具体任务、必读文档引用、允许的 Skill/工具、输出 Schema、预算、超时和不可做事项。
L4 私有工作区子 Agent 的临时草稿、候选分析和中间失败。不共享给其他 Agent，也不展示隐藏思维链。
L5 可审计交接包最终产物、证据、假设、未解问题、工具调用摘要和建议状态变更。经主 Agent/Reviewer 校验后才合并回项目上下文。

哪些情况必须共享上下文？

新 Agent 入群

AI PM、Builder 或 Reviewer 刚加入项目，需知道已批准事实、自己的责任和交付边界。

上下游交接

AI PM 把 PRD 交给 Builder，或 Builder 把可运行产物交给 Reviewer。

并行任务合流

调研、合规、财务等分支必须基于同一版 Brief，最后由主 Agent 合并冲突。

人工决定变更

用户修改范围、验收标准或安全边界后，所有活跃 Agent 必须切换到新 context_version。

缺陷与线上反馈

为了定位问题，Reviewer/Builder 需读取产品版本、上游需求、部署记录和反馈证据。

新版本分支

v1.0 已上线，新反馈建立 v1.1 分支；继承已批准主干，但不改写历史节点。

AIGC 画布模式参考与本产品裁决

官方来源可见模式可借鉴不直接照搬
FLORA Canvas无限方向探索，成熟路径可封装为可复用 Technique。保留生成分支，把已验证流程升级为模板。产品工厂不是媒体创作工具，不需要以图像为主节点。
Magnific Spaces无限画布 + 节点 + 可执行步骤 + 模板复用 + 团队反馈。节点显示输入/结果，工作流可复用，反馈直接附着在产物上。用户不应手动连接大量工程节点；主 Agent 维护图结构。
Recraft Studio / Krea单画布、自然语言编辑、实时生成与资产管理；Krea 增加 Nodes/Apps。对话负责指令，画布负责资产、版本和空间关系。不把所有生产操作都做成画布控件，避免用户承担编排。
ComfyUI Workflow节点输入/输出、类型连线、运行/错误状态、子图与局部执行。明确依赖关系、节点状态、阶段子图和只重跑受影响分支。不把技术组件暴露给非技术用户；节点表示产物和决策，不是底层算子。

双栏交互原型：团队群聊 + 产物画布

用户只与一个持续负责的主 Agent 对话。主 Agent 在阶段内自主调用 Skill、工具或邀请专业 Agent 入群；右侧画布持续沉淀证据、文档、原型、代码和审核结果。

主 Agent｜Factory Lead全程在场：对齐、编排、状态、人工闸与交付责任。
AI PM｜Product Lead按需入群：需求验证、BRD、MRD、PRD 和范围管理。
Builder｜Build Lead按需入群：交互、技术适配、代码、测试修复和部署。
Reviewer｜Independent QA独立入群：红队文档、模型冒烟、浏览器 QA 与放行。
17 岗位如何收敛： 调研、法务、财务、UI、Prompt、数据、部署、运营等不再默认作为独立 Agent，而是上述 4 个 Agent 按阶段调用的能力包。只有复杂 UI、高风险合规或并行研究需要独立上下文时，才临时升格为可见 Agent。

决策权与执行权合同
这四类权限必须同时存在。仅在 Prompt 中写“请谨慎”不构成系统控制。

        

          
Agent 可自主
  • 阶段内的路由、规划和任务拆分
  • 在白名单内调用角色、Skill 与工具
  • 可逆的文档/代码修改
  • 预算和次数内的重试与缺陷修复

          
人必须决策
  • 业务目标、Go/Hold/Kill 与 MVP 范围
  • 业务结果验收和已知问题接受
  • 费用、敏感数据、外部发送和正式发布
  • 修改全局 Harness、角色、Skill 和组织规则

          
Harness 强制
  • 项目状态与退出证据
  • 工具权限、参数校验、超时、步数和成本
  • 人工闸持久化与未审批阻断
  • 审计日志、证据链、回滚与密钥隔离

          
工具才能行动
  • 浏览器才能访问真实页面和登录状态
  • 终端、文件和 Git 才能产生可复现代码
  • 真实模型 API 才能完成 Agent 效果冒烟
  • 云 CLI 和 Secret 才能完成可追查部署

        

      

    


    

      

        
提示词目录审计与提取规则
只提取可执行方法、边界、Workflow、输出契约和评测标准。不提取无法验证的大厂履历、过度承诺和人设式语气。

    • 
              
  • audit/events.jsonl：每次路由、工具调用、成本、重试、错误、状态迁移和人工决策。
